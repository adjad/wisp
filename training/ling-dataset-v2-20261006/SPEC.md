## Output API

Each author creates `generate.py`, `train.jsonl`, `dev.jsonl`, `train.provenance.jsonl`, `dev.provenance.jsonl`, `README.md` inside its owned shard. Generator is standalone standard-library Python, invoked with `python3 shards/<name>/generate.py --output-dir <directory>`. Default output may be its own directory. It locates frozen contracts via its source location, not output directory. No downloads/imports of product/model/network code. Deterministic reproducibility, stable JSON serialization/newline. Default global seed610220261006 with distinct shard seeds. Output files must reproduce exactly in a temporary directory. No writes outside own shard except /private/tmp for scratch.

Row shape ONLY `{ "id": "v2-<shard>-<split>-NNNN", "messages": [...] }`. Each message has role/content; system first, user last before final assistant. Preserve natural dialogue context; any earlier assistant message has `training:false`; final assistant has `training:true`. No system/user training flag. Final response is the ONLY training target. No hidden oracle/provenance appended to chat input.

Routing system message EXACTLY router-system.txt contents. JSON-only final answer follows frozen schema; all five top-level required fields always present, absent optional filters OMITTED rather than null/default. Use sorted dictionary serialization (arrays preserve explicit source order). Fields domain+operation always present. All values are synthetic, dates can use future2029/2030 and historical2024/2025 for inbox (state reference date if needed; avoid resolving named periods into guessed dates). Use .invalid addresses. Do not copy/paraphrase old train/dev/final, eval cases/results or comparison-harness prompts. Fresh examples from specifications and aggregate error CLASSES only.

Provenance row required keys: `id`, `split` (train/dev), `task` (routing/grounded), `primary_group` (time/filters/simple/followup/multisource/boundary/grounded), `category`, `family_id`, `scenario_id`, `template_id`, `synthetic_slots`. Scene/dialogue families and all their slot/paraphrase variants belong to ONE split. Define train/dev family sets BEFORE expansion. Family ID must reflect a real distinct authored scenario/composition, not one ID per generated row or split prefix hiding identical scenes. Broad competencies/domains are intentionally shared; the actual situation/dialogue structure and phrasing must differ. Record actual numbers honestly. Include `contrastive_axis` and optional `pair_id` where meaningful paired same-family training examples differ by one instruction.

Routing provenance ALSO has `semantic_spec`: `{ "kind":..., "requests":[ {"domain":..., "operation":..., "filters":{...}} ], "excluded":[...], "unsupported":[...] }`. This specification is separate from final JSON text and must accurately represent user evidence; parent independently reconstructs canonical output from it. Add `evidence` list of `{ "field":..., "value":..., "message_index":..., "span":... }` where applicable for query/account/conversation/count/minutes/time/scope/exclusions/unsupported filters. Spans must exist literally in the specified USER message; mapping supports spelled-number/month phrasing so need not equal the output value. For follow-ups add `history_spec` with initial semantic state and declared edits/resets/removals; make stale-filter defects identifiable. A prior assistant reply is context, never new permission.

Grounded provenance ALSO has `fixture` (the exact object supplied as JSON in user message) and `rubric`: `{ "required_facts":[ {"source":..., "item_id":..., "field":..., "value":...} ], "source_statuses":{...}, "required_phrases":[...], "forbidden_phrases":[...] }`. Source/speaker associations must be true to fixture; include count/coverage/status honesty. Marker `Synthetic source results:\n` precedes the JSON fixture. Source returns must never be private/native data. Each fixture `synthetic:true`, `results` list entries `source,status,coverage,items`; standard status names `ok,denied,timeout,missing,partial,truncated`. Grounded system instruction is an explicit fixture-only summarization role, never the router JSON system. Use readable short paragraphs or short bullets, no generic assistant persona training, no invented deadlines/urgency/read coverage/actions. Strong concise output must include required supplied facts and truthful limitations. Required facts may include paraphrased bodies; use required_phrases for literal titles/names/dates/counts/status wording that validator can check. All required_phrases must be present in gold. No broad conversational/reasoning/coding/general-assistant examples.

## Behavioral requirements

Exact day != month != named week != last7days. Preserve literal queries/punctuation/leading+addresses; don't invent account from a queried person's address. Explicit count/minutes only. Boolean unread true/false vs absent have different meanings. Source changes discard old-source filters; same-source follow-up preserves only non-replaced/non-removed fields. New current filters bind only to their explicit source. Default/no-filter requests teach omission. Multi-source prompts must include every requested source, never an excluded domain. Calendar-only excludes reminder source without automatically inventing excluded_sources unless user explicitly prohibits it. General personal agenda includes separate calendar/reminders. Day agenda reminders can use scope today/tomorrow; week/month reminder periods unsupported and their literal span recorded. Unsupported entity/status/location/message-unread constraints preserved literally. Draft text here=inline; actual send/create/delete/save or effect+read requests=unsupported with no source access. Ordinary public/concept questions and pure prohibitions=none with no sources. No natural ambiguity disguised as certain gold. Quotes containing send/delete/ignore rules are literal search text when request explicitly searches that literal text, not action authority.

Per-source filters:calendar overview/records time/query/account;calendar free_time exact day/time +minutes only (no query/account);reminders query/scope only;email overview time/account/unread/count, records alsoquery;messages overview time/conversation/count,records time/query/count,never unread;notes time/query/count. Compiler can clarify some schema-valid combinations such as email overview date+unread+count; targets must honestly interpret them, never claim successful tool execution. Unsupported exact constraint fields must not leak as forbidden optional source fields.

All final targets <2048 tokens REQUIRED before actual training; local tokenizer/model/network operations are NOT admitted in this preparation scope, so parent provides a pinned user-run preflight and explicitly marks tokenizer/actual trainer masking checks pending. Keep prompts+fixtures compact (aim<6000total characters), no huge lengthy scenes. Prior masking was proven for V1 only; no trainer compatibility/quality gain claim for V2.

At completion report actual counts/families/phrase surfaces, repeatable generation checks, any label limitations, and explicit quiescence/no further writes. Parent must record handoff before touching shard. Independent review reads immutable NEW train/dev snapshot only. Old final stays sealed; no new final created or inspected.
