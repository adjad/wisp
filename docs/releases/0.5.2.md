**Wisp 0.5.2** fixes two problems with cloud models. It changes nothing else. Everything in the [0.5.1 notes](0.5.1.md) and the [0.5.0 notes](0.5.0.md) still applies unless it is listed here.

## What's fixed

### Settings > Models > Cloud > Everything

- **Connecting with "Everything" always failed.** Wisp's service accepted the connection, but the app refused the service's answer because it did not expect "everything" in the list of roles, so the cloud model was never switched on.
- **Now** the app accepts that answer. "Everything" is only accepted on its own, never mixed with another role.

### The macOS question for your saved cloud key

- **macOS could ask for your login password more than once, or the question could pile up.** The first time Wisp reads a cloud key you saved, macOS asks whether Wisp may use it. Several reads at once, and status checks repeating a read you had just refused, could each put the question back.
- **Now** Wisp reads the key one at a time. A read that finds another one waiting on macOS's question gives up after a few seconds instead of queueing a second question. After a refusal, Wisp waits 20 seconds before asking again, except when you click Connect. A read has up to a minute for you to answer, and choosing **Always Allow** makes later reads silent.
- **Connect with "Everything" asks for the key once, up front,** while you are at the button. If Wisp cannot read it, Connect says so and asks you to try again and choose Always Allow. Nothing is moved to the cloud model until the key is read.

## What was and was not tested

- Both fixes are checked by Wisp's tests, which use a stand-in for the Keychain. They have not been tried by hand with a real cloud key and real macOS questions on Apple silicon.

## Upgrading

- Nothing to do. Your model, settings and permissions are kept. If Connect with "Everything" failed for you before, try it again.

## Known issues

- All of 0.5.1's known issues still apply, including: **if you first opened Wisp on a macOS older than 26.2 and setup still says "Wisp is set to use another app for its model",** open Settings > Models and switch the engine to **Built-in engine**, or delete the `engine:` lines from `~/.moe/config.yaml` and reopen Wisp.
- **A key read refused within the last 20 seconds** makes background checks report the cloud model as unavailable for that time. Clicking Connect asks again straight away.
