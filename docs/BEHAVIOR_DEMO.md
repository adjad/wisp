# Behavior demo: Wisp learns your routines and acts before you ask

**Everything shown in this demo is fictional.** Aria Solano, her company
Cedarloop, and every contact, meeting, reminder, note and message are made up.
The data comes from `service/behavior/persona.py` and
`service/demo/founder-demo.json`. Every seeded item lives in a container named
**Wisp Demo** and carries a `[wisp-demo-id:…]` marker. Cleanup removes all of
it.

Wisp learns Aria's routines from her calendar and message rhythm. It predicts
tomorrow and pushes a few useful **nudges** before she asks. Code finds the
patterns as plain statistics, with evidence counts. The model only writes the
sentences. How it works: [BEHAVIOR_ENGINE.md](BEHAVIOR_ENGINE.md). GX10 side:
[gx10/RUNBOOK.md](gx10/RUNBOOK.md).

> **Short on time? Do only this:**
> 1. `python3 demo/seed_mac_persona.py seed --calendar` (Calendar is all the
>    Intel build reads).
> 2. Launch the demo build. Notifications on, style **Alerts**, Focus off.
> 3. Ten minutes before going on: `.venv/bin/python demo/wisp_demo.py behavior reset --wait`
>    (removes rehearsal drops from **Wisp Demo**, waits about 75 s for one
>    Calendar sync, then resets), then `behavior run` and `behavior nudges`.
> 4. On cue: beats 1 and 2, then `drop --preset gym-conflict` (beat 5) and
>    `drop --preset backtoback` (beat 6).
>
> Plan B is near the bottom.

## What the audience sees, by build

| | Founder / Intel build (`WISP_FOUNDER_DEMO`, `WISP_REMOTE_ONLY`) | MacBook, Apple silicon (oMLX / Ling) |
| --- | --- | --- |
| Behavior learning | On automatically, synthetic data only | Launch with `WISP_BEHAVIOR=1 WISP_BEHAVIOR_SYNTHETIC_ONLY=1` |
| Where the engine runs | In the Mac backend (`brain.mode local`) by default. The GX10 brain server is optional | Same |
| Chat answers and tools | `qwen3.6:35b` on the GX10 through the token gateway. The four behavior tools are allowed by the remote-only policy, and the learned profile card is the only personal context in the prompt | Local oMLX / Ling |
| Nudge wording | The GX10 rewords up to 2 nudges per pass (6 s each). On a timeout the nudge shows its code-composed text. Both read fine | The local model, only if it is already loaded (never a cold load). Otherwise code text |
| Notification | macOS alert: title, body, evidence line, subtitle **"Already done: … · Undo available"**, buttons Undo / Do it / Useful / Not now / Wrong | Same |
| Card in the panel | Yes, up to 3 cards at the top | Same |
| Wisp-schedule reminder from an auto action | Created and undoable, but **never fires**: this build has no scheduler. The nudge notification is what shows | Created, and fires at its own time (the evening before the clash, not on stage) |
| Reminders and Notes seeds | Not read by this build. Calendar is what matters | Seeded and visible to other features. Never used for learning |

**Latency on the Intel build.** Nudge rewording sends up to 2 short requests
per pass to the GX10 (it never runs while a chat request is in flight). If the
GX10 feels slow in rehearsal, turn rewording off for the live run; nudges then
show their code-composed text, which reads fine. The backend inherits the
app's environment, so either start the app binary from Terminal
(`WISP_BEHAVIOR_PHRASER=0 /Applications/Wisp.app/Contents/MacOS/Wisp`, keep
the window open) or run `launchctl setenv WISP_BEHAVIOR_PHRASER 0`, then quit
and reopen Wisp normally (`launchctl unsetenv WISP_BEHAVIOR_PHRASER` after the
demo).

## Setup (start at least 30 minutes before 1 PM)

1. **Quit Wisp**: menu-bar icon, then Quit.
2. **Seed the persona** into the Mac's apps. Use the system Python. No
   virtualenv is needed.

   ```sh
   python3 demo/seed_mac_persona.py seed --dry-run | tail -3   # preview counts, writes nothing
   python3 demo/seed_mac_persona.py seed                       # Calendar + Reminders + Notes
   python3 demo/seed_mac_persona.py seed --calendar            # Calendar only (enough for the Intel build)
   ```

   On the first run, macOS asks you to let Terminal control Calendar,
   Reminders and Notes. Allow all three. Seeding takes a minute or two and
   sends about 50 items per `osascript` call. Rerunning is safe because items
   that already exist are skipped. Times use the Mac's own time zone.
   If Calendar won't create the calendar, create a calendar named
   `Wisp Demo` in Calendar.app, then rerun.

   You can also run `.venv/bin/python demo/wisp_demo.py persona seed`.
3. **Launch Wisp with behavior learning turned on.**
   - **Founder / Intel demo build:** open the app normally. Behavior learning
     and synthetic-only mode turn on automatically.
   - **Any other build:**

     ```sh
     WISP_BEHAVIOR=1 WISP_BEHAVIOR_SYNTHETIC_ONLY=1 \
       /path/to/Wisp.app/Contents/MacOS/Wisp
     ```

     Keep that Terminal window open. The flags only reach Wisp when you start
     the app binary this way. `WISP_BEHAVIOR_SYNTHETIC_ONLY=1` makes Wisp learn
     only from the persona and the **Wisp Demo** calendar. It never learns
     from your real Messages, Reminders, Notes or questions you ask.
4. **Notifications.** Go to System Settings > Notifications > Wisp. Turn
   notifications on and set the style to **Alerts**, so the buttons stay on
   screen. Turn off Focus / Do Not Disturb.
5. **Warm up** from a second terminal with the repo venv (the script needs the
   repo's Python packages):

   ```sh
   .venv/bin/python demo/wisp_demo.py behavior status     # enabled, observation counts
   .venv/bin/python demo/wisp_demo.py behavior run        # ingest + mine + nudge now
   .venv/bin/python demo/wisp_demo.py behavior patterns   # what it learned (with ids)
   .venv/bin/python demo/wisp_demo.py behavior predict    # tomorrow
   .venv/bin/python demo/wisp_demo.py behavior profile    # the always-on "who you are" card
   ```

   The persona contains these planted routines. Check that `patterns` finds
   them:
   - **Morning lift**, Mon/Wed/Fri 6:45–7:45, about 85% of weeks
   - **Focus block**, weekdays 9:00–11:00
   - **Messages with Dev Malik** on weekday afternoons (learned window about
     2–5 PM), plus a Thursday 3 PM 1:1
   - **Calls with Mom** on Sunday evenings
   - On Tue/Thu afternoons she has 3–4 back-to-back meetings and cancels the
     **last one** about 60% of the time
   - When a meeting is booked over the gym, she moves it 4 times out of 5

   The seeded upcoming two weeks already contain a meeting over the next gym
   morning and a back-to-back run on the next Tue/Thu. Nudges only look
   through the **end of tomorrow**, so only what falls in that window fires
   now. The `drop` presets below create fresh triggers on cue.
6. Open the Wisp panel once to confirm it's healthy. Clear the conversation
   with **New chat**.

## Rehearsal: always start with a reset

Rehearsals use up the nudge budget (4 per day), and a "Not now" or "Wrong" you
click can mute a kind of nudge for a week. Before each rehearsal, and again
about 10 minutes before the real run:

```sh
.venv/bin/python demo/wisp_demo.py behavior reset --wait   # 1. delete the events earlier `drop`s added to
                                                           #    "Wisp Demo" ([wisp-demo-id:drop-…] only)
                                                           # 2. wait for one Calendar sync (~75 s)
                                                           # 3. POST /behavior/clear: forget learned state,
                                                           #    delivered nudges, Wisp-schedule items it made
.venv/bin/python demo/wisp_demo.py behavior run     # re-learn from the persona, nudge now
.venv/bin/python demo/wisp_demo.py behavior nudges  # what already fired
```

Why the drop cleanup matters: a rehearsal `drop` leaves its meeting in the
**Wisp Demo** calendar. Without the cleanup it refires right after the reset,
and the real drop then only says "already there". Use `--dry-run` to print the
AppleScript instead. Without `--wait`, `reset` removes the drops and stops,
telling you to rerun it a minute later (resetting before Calendar syncs would
refire them). `behavior clear` is the same command. Off macOS the calendar
step is skipped with a message.

`curl -s -X POST http://127.0.0.1:8765/behavior/reset` resets Wisp's learned
state only (no calendar cleanup). Reset works only in synthetic mode. It never
touches real data or the seeded persona items in **Wisp Demo**. Expect:

- Right after launch, nudges wait for Wisp's first Calendar read (up to about
  3 minutes; `behavior run` prints "waiting for Wisp's first Calendar read").
  This keeps the seeded calendar and the persona from nudging twice about the
  same meeting. With Calendar access off, the persona alone is used after 3
  minutes.

- Anything seeded inside the look-ahead, such as the persona's meeting over
  tomorrow's gym time, fires again within about 30 seconds. That nudge can be
  your first live card.
- Cards already shown in the panel may stay until you dismiss them (the x).

## Demo beats

Type each prompt exactly into the Wisp panel.

### 1. "What do you know about me?"

Expected: a short profile. Aria lifts Mon/Wed/Fri mornings and protects 9–11
for focus. She talks to Dev on weekday afternoons and calls Mom on Sundays.
She tends to drop the last of a long run of meetings. The answer includes
evidence ("seen 21 of 24 times; confidence 76%").

*Talking point (personal context):* Aria didn't fill in a profile. Wisp
learned it from what her Mac already shows about her week. If a pattern is
wrong, she can reject it, and it stops driving predictions and nudges:
`.venv/bin/python demo/wisp_demo.py behavior patterns --reject <id>`.
"Describe me" and "What are my habits?" work too.

### 2. "What will tomorrow look like?"

Expected: tomorrow's likely shape. This covers the gym (if it's a gym day),
the focus block, any meeting at risk of being cancelled, any clash with the
gym, and when Dev is likely to reach out. Each item comes with a probability
and a reason. "Predict my day" works too.

### 3. "When do I usually work out?"

Expected: "Mon/Wed/Fri around 6:45–7:45," with how consistent it is.

### 4. "Which meetings do I usually cancel?"

Expected: the last meeting of a 3+ back-to-back run, about 60% of the time.
Meetings booked over the gym usually get moved.

Avoid "What do you know about my week?". It doesn't match the behavior
phrases and goes to the normal router.

### 5. Gym conflict: Wisp acts on its own, with Undo

```sh
.venv/bin/python demo/wisp_demo.py drop --preset gym-conflict
```

This books the fictional "Foundry export check-in" for 7:00–7:45 on the next
gym morning (tomorrow if tomorrow is Mon/Wed/Fri) in the **Wisp Demo**
calendar, then runs the engine.

Expected: an alert "Foundry export check-in overlaps your workout". The
subtitle reads **"Already done: Remind me · Undo available"**. Wisp has
already added a reminder to Wisp's own schedule. Click **Undo**: the reminder
is removed and Wisp confirms. The same card appears at the top of the Wisp
panel, with a **Draft a move request** button (the alert's **Do it**).

Wisp reads Calendar about once a minute. If no nudge appears within a minute
or so, run `behavior run` again.

*Talking point (proactive, safe):* Wisp only acts on its own when the action
is reversible and stays on Wisp's own schedule. Undo is always one click away.
It never edits Apple Calendar or Reminders by itself.

### 6. Back-to-back: "Likely skip" plus a drafted note that isn't sent

```sh
.venv/bin/python demo/wisp_demo.py drop --preset backtoback
```

This adds four fictional meetings tomorrow, 14:00–16:00, back to back.

Expected: "You might skip Board deck prep" (the last one). A **"Likely
skip"** tentative hold is placed (Undo available). There is also a **"Draft
reschedule note"** button (the alert's **Do it**). Click it: the Wisp panel
opens with a reschedule request **prefilled in the composer and not sent**.
Review it and press Return only if you want. Anything that would send still
goes through Wisp's normal confirmation card.

*Talking point:* Wisp never sends a message or changes a real meeting from a
nudge. It drafts, and the user decides.

### 7. Dev's afternoon window

```sh
.venv/bin/python demo/wisp_demo.py drop --preset dev
```

This adds nothing to the Mac. It runs the engine and prints Dev's predicted
contact window. A **contact window** nudge fires only inside the window (about
2–5 PM) and only when Dev's last message has waited unanswered for 2 hours or
more. **At 1 PM it will not fire.** Show the printed prediction instead. On a
weekend there is no Dev window at all.

### 8. Teaching it

Click **Not now** or **Wrong** on a nudge. Two of those for the same kind in a
week mute it for 7 days. **Useful** raises its priority. Nudges have a daily
budget of 4 and stay quiet from 22:00 to 07:00. **Undo** counts as a negative
vote too, and turns that nudge's auto action into an offer next time.

## Talking points

- **Proactive.** Wisp doesn't wait for a question. It notices the gym clash
  and the meeting that's likely to be skipped, then acts or offers to.
- **Personal context.** The answers come from Aria's own routine, with
  evidence. They aren't generic advice. She can confirm or reject what it
  learned.
- **Privacy.** In this demo the behavior engine runs **on the Mac** as a
  local SQLite database (`~/.moe/behavior.db`, or under `WISP_HOME`). Code
  finds the patterns. For real Messages, Wisp only records direction, contact
  and time, never the text. The GX10 runs chat inference and rewords the short
  sentences. It receives the few facts needed for one sentence, not the
  timeline. An optional remote-brain mode can also run the learning on your
  own GX10.
- **Honest scope.** Today's data is fictional and clearly labeled. With the
  flags removed, the same engine learns from your own Calendar, Reminders
  and message metadata.

> **Kill switch:** if behavior learning misbehaves live, relaunch with `WISP_BEHAVIOR=0`. That turns it off even in the founder build, and the rest of Wisp is unchanged.

## Plan B

| If… | Do this |
| --- | --- |
| Notifications are off or don't show | Use the **card at the top of the Wisp panel**. It has the same buttons: Undo, the draft button, Useful / Not now / Wrong. |
| The GX10 is down or slow | Nudges, cards and Undo still work with the **code-composed text**. In the Intel build, chat questions (beats 1–4) need the GX10, so show `behavior patterns`, `behavior predict` and `behavior profile` in Terminal instead. |
| A nudge doesn't show | `.venv/bin/python demo/wisp_demo.py behavior run`, then `.venv/bin/python demo/wisp_demo.py behavior nudges`. If it is listed, it was delivered: point at the card in the panel. |
| `drop` says "already there" | The event is still in **Wisp Demo** from a rehearsal. `drop` still runs the engine and prints that event's existing nudge. To fire it fresh: `behavior reset --wait`, then `drop` again. |
| `behavior run` says "busy" | A scheduled pass (mining, or a slow GX10) is still running; `run` waited 30 s. Rerun it. |
| `behavior run` says "no new nudge" | It already fired (a nudge never fires twice until a reset), it is outside the look-ahead, it is quiet hours (22:00–07:00), the 4-per-day budget is spent, or the kind is muted. Run `behavior reset --wait`, then `behavior run`. |
| A `drop` produced nothing | Wisp reads Calendar about once a minute. Wait, then `behavior run`. Check the event is in the **Wisp Demo** calendar. |
| The demo script won't start (missing packages) | Use `curl`: `curl -s -X POST http://127.0.0.1:8765/behavior/run`, `curl -s http://127.0.0.1:8765/behavior/nudges`, `curl -s -X POST http://127.0.0.1:8765/behavior/reset`. |
| Everything is broken | Show `behavior patterns`, `behavior predict` and the profile card, and say the rest is the same engine. |

`behavior status` shows `enabled`, the active engine (`local` or `remote`),
observation counts and any `errors`. To preview the AppleScript a drop or seed
would run, add `--dry-run`. It writes nothing.

## Cleanup

1. **Quit Wisp first.** If Wisp is still learning when the **Wisp Demo**
   calendar disappears, it would record every upcoming demo meeting as
   "cancelled". (Run `behavior clear` before quitting if you also want the
   reminders and holds nudges added to Wisp's schedule gone.)
2. Remove the seeded data. This deletes only the containers named
   **Wisp Demo**: the calendar, the Reminders list, and the Notes folder in
   every account.

   ```sh
   python3 demo/seed_mac_persona.py remove          # shows counts, asks before deleting
   ```

   Notes moves deleted notes to **Recently Deleted**. Empty that folder if
   you want them gone right away.
3. Forget what Wisp learned. `behavior clear` (before step 1) does this. Or,
   with Wisp quit, delete the files. Use your `WISP_HOME` instead of `~/.moe`
   if you set one.

   ```sh
   rm -f ~/.moe/behavior.db ~/.moe/behavior.db-wal ~/.moe/behavior.db-shm \
         ~/.moe/behavior_runtime.db ~/.moe/behavior_profile_card.txt
   ```

   Auto-added reminders and holds on Wisp's own schedule can also be undone
   from their nudge (`behavior nudges --undo <id>`). Otherwise they pass with
   their time.
4. Relaunch Wisp normally, without `WISP_BEHAVIOR`. Behavior learning is off
   by default except in the founder demo build.
