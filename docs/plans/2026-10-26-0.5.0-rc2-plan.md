### 1. Ask by voice (already built)

The mic in Ask, the Brief/Day header mic and ⌥⇧Space record up to 30 s. The
recording ends on a pause. The clip goes to `POST /voice/transcribe`, which
hands it to **Gemma 4 E4B itself** through oMLX `input_audio`, so no second
model is needed. Three test clips were transcribed word for word in
0.9–1.2 s with the model warm. The endpoint refuses any model without an
audio encoder, and any endpoint that isn't the local engine. Answers are read
aloud with the Mac's voice.

For rc2:

- **Fix the red Simulation QA** on #367. The owning session diagnoses it.
- **Make transcription a foreground turn.** `service/voice.py` waits while a
  generation is in flight (`idle.in_flight`), but never calls
  `idle.begin_foreground()`. So the Brief's mail overviews (and, from rc2,
  mail memory) can start the moment you speak, and your words wait behind
  them; a mail-overview call can take up to 120 s. Wrap the transcription in
  `begin_foreground()`/`end_foreground()`: background jobs then skip, and
  cancel a call already running. **This is a cross-feature blocker for rc2.**
- Microphone permission is asked only on the first mic press (already done).
- A Release Auditor review is required: microphone entitlement, a new native
  capture path, and audio sent to the model.

### 3. Mail memory, phase 1

Design and measurements: `docs/plans/2026-10-26-email-digest-memory-research.md`.

- **How it reads mail.** The Swift app reads Mail's `Envelope Index` and
  `.emlx` files, because Full Disk Access belongs to the app and the backend
  can't share it. The backend asks for one message at a time.
- **Model and dates.** One Gemma call per email, thinking off. Dates are
  resolved in code, which fixes Gemma's "by Friday" error.
- **Queue and scheduling.** A persisted queue. Calls run only between turns
  (≥ 2 min after a turn, 90 s apart) or while you're away (≥ 10 min with no
  input, on power). A turn cancels any call in flight.
- **What you see.** Suggestions appear on the Brief, and Add writes to Apple
  Reminders.
- **Which mail.** Inbox and Sent only, so never spam, trash or archive.
  Mail's Primary, Transactions and Updates categories are read; Promotions
  never are. For Gmail accounts connected through the API, Gmail's
  Promotions, Social and Forums tabs are skipped too. On this Mac that is
  about 1,120 emails over 90 days, most of them Updates.

Built: the backend store, queue and extraction; the runner with its idle
levels; the API, with `_native_only`, `read_only`, an `app_connected` check
and single-use request ids; the Brief row; and tests.

Still to do: a shadow/live switch in the UI (after #367, which changes
QuickSettingsView), a rebase onto the rc2 integration branch, and the release
notes.

#### The importance bar (the user's decision, 2026-10-26)

Mail memory runs in the background by default (mode `live`). The Brief shows
a suggestion only when it is important. Everything else is stored with the
reason it was held back. Code decides (`service/mail_memory/importance.py`),
from the item's verbatim quote and the email's index metadata; the model is
never asked what matters.

A suggestion is shown only when it is due within **30 days**, is not
suspicious, and has one of these reasons:

| Reason | When |
| --- | --- |
| `yours` | Your own Sent mail promised it |
| `person` | A real person wrote to you: Inbox, not bulk, Mail's Primary category or none |
| `money` | A payment, bill, invoice, rent, fee, tuition, refund, tax or an amount |
| `account` | Something that expires, renews or has a security problem: passport, licence, visa, insurance, lease, contract, subscription, password, sign-in |
| `deadline` | A dated deadline, appointment, booking, RSVP, interview or exam, from a person or Mail's Transactions category |

Never shown: suspicious items, sales and offers, and automated mail
(newsletters and notifications: bulk, or Mail's Updates category) whose only
reason is a deadline. Automated mail is shown only for money or an account
issue. A suggestion due later than 30 days stays stored and appears once it
is within the window.

Held-back items are logged per tick (`why=` counts) and counted in the
endpoint's `stats.why`, so the bar can be tuned from real counts.
`shadow` (record only, show nothing) and `off` remain available.

Known limit: phase 1's "Add to Reminders" can't attach the source email to
the reminder. The native writer accepts only title, due date and kind, and
widening that strict whitelist is its own reviewed change. The Brief row
keeps "Open email" instead.

A Release Auditor review is required: new persisted data, a native read of
Mail's files, and writes to Reminders.

## Shared-model rules

All three features use the one resident Gemma. In rc2 the order is:

1. A **user turn**: typed Ask, **voice transcription** (once it is a
   foreground turn), the agent loop.
2. **Mail overviews** (`mail_gists`, every 15 min at most).
3. **Mail memory**: one ~1–2.5 s call per tick, skipped while either of the
   above is running.

Mail memory never loads or swaps a model, so it never makes a voice question
slower than one cancelled call.
