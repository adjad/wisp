**Wisp 0.5.2** fixes two problems with cloud models. It changes nothing else. Everything in the [0.5.1 notes](0.5.1.md) and the [0.5.0 notes](0.5.0.md) still applies unless it is listed here.

## What's fixed

### Cloud "Everything" in Settings

- **Settings > Models > Cloud could not load or save when "Everything" was set.** On Apple silicon, "Everything" (all of Wisp on the cloud model) is only set by hand in `~/.moe/config.yaml`; Settings has no switch for it. When it was set, Wisp's service reported it, but the app refused that answer because it did not expect "everything" in the list of roles.
- **Now** the app accepts that answer. "Everything" is only accepted on its own, never mixed with another role.

### The macOS question for your saved cloud key

- **macOS could ask for your login password more than once, or the question could pile up.** The first time Wisp reads a cloud key you saved, macOS asks whether Wisp may use it. Several reads at once, and background checks repeating a read you had just refused, could each put the question back.
- **Now** Wisp reads the key one at a time. A read that finds another one waiting on macOS's question gives up after a few seconds instead of queueing a second question. After a refusal, background reads wait 20 seconds before asking again; Connect asks straight away. A read has up to a minute for you to answer. Choosing **Always Allow** makes later reads silent; choosing **Allow** means macOS asks again at the next read.
- **Connecting with "Everything" asks for the key once, up front,** while you are at the button, and Settings now waits long enough for you to answer. If Wisp cannot read the key, Connect says so and asks you to try again and choose Always Allow. Nothing is moved to the cloud model until the key is read.

## What was and was not tested

- Both fixes are checked by Wisp's tests, which use a stand-in for the Keychain. They have not been tried by hand with a real cloud key and real macOS questions on Apple silicon.

## Upgrading

- Nothing to do. Your model, settings and permissions are kept.

## Known issues

- All of 0.5.1's known issues still apply, including: **if you first opened Wisp on a macOS older than 26.2 and setup still says "Wisp is set to use another app for its model",** open Settings > Models and switch the engine to **Built-in engine**, or delete the `engine:` lines from `~/.moe/config.yaml` and reopen Wisp.
- **A key read refused within the last 20 seconds** makes background checks report the cloud model as unavailable for that time. Clicking Connect asks again straight away.
- **If you choose Allow rather than Always Allow at Connect,** macOS may ask a second time during the same Connect, when Wisp tests the model.
